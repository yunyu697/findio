## 6. 验签（ReleaseTool verify）

1. CI 内：tag run `43705189156` 在「发布 GitHub Release（仅 tag）」一步执行
   `ReleaseTool create`（seed 签名）→ `ReleaseTool verify --manifest dist/latest.json` → 通过后才上传清单。
2. 本地复核：下载 Release 上的 `latest.json` 与 `latest.json.sig` 后执行

   ```
   dotnet run --project src/Findio.ReleaseTool -- verify --manifest <下载目录>/latest.json
   ```

   输出「验签通过: …（version=1.2.0）」，退出码 0，即签名私钥（Secret 内容）与客户端内置公钥匹配。

## 6.1 发布说明修正与清单重签（发现的自身缺陷）

tag 触发时 `docs/1.2.0-发布说明.md` 抬头仍写着「未发布」，Release body 与清单 `notes` 字段都照抄了这段文字，
而更新窗口会直接展示 `notes`（`UpdateWindow.xaml.cs` 的 `NotesText`）——即已发布的 1.2.0 会在更新界面里自称「未发布」。
修正方式（不动 tag、不重建二进制）：

1. 文档抬头改为「已发布」并补远端数据，提交 `7e2f566` 后推送 `main`（`872a458..7e2f566`）。
2. `gh release edit v1.2.0 --notes-file docs/1.2.0-发布说明.md` 覆盖 Release body。
3. 重新生成清单：`ReleaseTool create`，输入为**从 Release 下载回来的同一对二进制**（size 与 SHA256 与资产 digest 逐位一致：
   8,630,181 / `5de529d6…`、11,713,531 / `8beb3cb8…`），`--released-at` 保持 `2026-11-15T10:42:03Z`，
   seed 为本地私钥原文件；`ReleaseTool verify` 通过后 `gh release upload --clobber` 覆盖 `latest.json` 与 `latest.json.sig`。
4. 复查：`releases/latest/download/latest.json` 200、12,577 字节、`sha256 23ef92f9…`，`notes` 首行为「状态：已发布」，
   文中已无「未发布」字样。
