# Pathleap 1.0.8 发布说明

发布日期：2026-11-13
版本：`1.0.8`（上一正式版 `1.0.7`）
tag：`v1.0.8`

版本号按 [版本号规则](版本号规则.md) 从 `1.0.7` 升 patch 得到 `1.0.8`（未超过 10，不进位）。

本版只改**主搜索窗的尺寸与位置**：宽度从固定 660 DIP 改为光标所在显示器工作区宽度的一半，
唤醒时顶边固定在工作区高度的 1/4 处（原来按 1/5 定位、垂直方向接近居中）。高度保持 436 DIP 不变。
索引、搜索、更新与其它界面不变。

## 1. 主搜索窗：半屏宽 + 顶边 1/4

### 1.1 规则

| 项 | 1.0.7 及更早 | 1.0.8 |
| --- | --- | --- |
| 宽度 | 固定 660 DIP | 光标所在显示器**工作区宽度的 1/2**（DIP 计算后换算物理像素） |
| 水平位置 | 工作区居中 | 工作区居中（不变） |
| 顶边 | 工作区高度 × 0.2 | 工作区高度 × **0.25**（不随窗口高度居中） |
| 高度 | 436 DIP | 436 DIP（不变） |
| 窄屏下限 | 无（660 固定） | 半宽低于 **560 DIP** 时取 560 DIP，且不超过工作区宽度 |

目标屏幕与设置窗一致：取**光标所在显示器**，`MonitorFromCursor` 失败时退回主屏，复用同一套降级路径。
宽度先按 DIP 求一半再一次性换算物理像素，避免逐次取整导致高 DPI 下宽度抖动；`X` 按
`工作区左 + (工作区宽 − 窗宽) / 2` 整数计算，同一缩放档下每次唤醒位置一致。

实现：`src/Pathleap.UI/Platform/MainWindowLayout.cs`（新增），`MainWindow.PositionWindow`
改为调用它；`AppConfig.WindowWidth` 已失效并移除，`WindowHeight` 保留。

### 1.2 实拍核对

`--layout-probe`（`GetDpiForMonitor` 真实读数）闸门确认缩放后，用 `BitBlt(CAPTUREBLT)` +
`DWMWA_EXTENDED_FRAME_BOUNDS` 抓物理像素，再按工作区边界算比例：

| 缩放 | 窗宽 / 工作区宽 | (窗顶 Y − 工作区顶) / 工作区高 | 水平居中偏差 | 窗高 |
| --- | --- | --- | --- | --- |
| 200% | 1440 / 2880 = **0.5** | (426 − 0) / 1704 = **0.25** | 0 px | 872 px（436 DIP） |
| 100% | 1440 / 2880 = **0.5** | (438 − 0) / 1752 = **0.25** | 0 px | 436 px（436 DIP） |

- 200%：工作区 2880×1704（底部任务栏 96 px），窗 `L=720 T=426 1440×872`；
- 100%：工作区 2880×1752（底部任务栏 48 px），窗 `L=720 T=438 1440×436`；
- 截图：`44-main-scale200-recent` / `45-main-scale200-results` / `46-main-scale100-recent` /
  `47-main-scale100-results`（均在 `docs/shots/`）；
- 125% / 150% **未实拍**：本机两块屏当前均为 200%，只切了 100% 一档做对照；
  两档与合成三屏（左 150% / 主 125% / 右 100%）、1024 DIP 窄屏下限由探针 `mainWindow` 节点数值留档。

> **几何口径（2026-11-15 补注，2026-11-15 按原始读数复核）**：上表数字均为 `DWMWA_EXTENDED_FRAME_BOUNDS` 物理像素，窗宽 = 光标所在显示器**工作区物理宽的一半**（`MainWindowLayout.Compute`），不是固定 1440。
>
> 本轮复测机的原始读数（per-monitor v2 DPI aware 进程，`EnumDisplayMonitors` → `GetMonitorInfoW` / `GetDpiForMonitor`，2026-11-15）：
>
> - 唯一显示器 `\\.\DISPLAY16`，`primary=True`；
> - `rcMonitor` = `(0,0)-(2940,1846)`，即 2940×1846；
> - `rcWork` = `(0,0)-(2940,1750)`，即 2940×1750（底部任务栏 1846−1750 = 96 px = 48 DIP）；
> - `GetDpiForMonitor(MDT_EFFECTIVE_DPI)` 返回 hr=0，X=192、Y=192 → 200%；
> - `GetSystemMetrics`：`SM_CXSCREEN=2940`、`SM_CYSCREEN=1846`；
> - `EnumDisplaySettingsW(\\.\DISPLAY16, ENUM_CURRENT_SETTINGS)`：2940×1846 @144 Hz、`dmLogPixels=192`、32 bpp；`ENUM_REGISTRY_SETTINGS` 同值。
>
> 代入 [`MainWindowLayout.Compute`](../src/Pathleap.UI/Platform/MainWindowLayout.cs)：`workWidth=2940` → `workWidthDip=2940/2=1470` → `widthDip=min(1470, max(560, 1470×0.5))=735` → `widthPx=Round(735×2)=1470`（整除，取整未参与）；`heightPx=Round(436×2)=872`；`X=0+(2940−1470)/2=735`（整数除法）；`Y=Round(1750×0.25)=Round(437.5)=438`（`Math.Round` 默认银行家舍入，437.5 → 438）。本轮拉起窗口实测 `EXT=(735,438)-(2205,1310) 1470×872`、`GetDpiForWindow=192`，左右留白各 735，无偏移。
>
> 即 **1470 由 `rcWork` 原始读数 2940 二分得到，不是从窗宽反推**。同一函数代入上表的工作区 2880×1704 得 `X=720 Y=426 1440×872`，与上表逐项一致——代码未变，变的是显示模式：当时远程会话桌面为 2940×1846@144 Hz，而 1.0.5 / 1.0.8 记录的是 2880×1800@60 Hz（物理面板原生）。`Win32_VideoController` 当前同时列出 `AMD Radeon 780M 2880×1800@60`、`GameViewer Virtual Display Adapter 3840×2160@144`、`OrayIddDriver Device`（空值），当前会话的桌面模式是 2940×1846@144 Hz；1.0.7 设置窗居中记录（中心 1470/875）也与 2940×1750 工作区一致，说明该环境此前已出现过。据现有读数只能判定为**环境变化（显示模式/虚拟显示会话）**，无法在本机区分是换屏、改分辨率还是远程会话切换；代码侧按同一规则复算无误，不作缺陷处理，回到 2880×1800 桌面会重新得到 1440×872。另注意：`GetWindowRect` 在 DPI 不感知的宿主里会返回虚拟化坐标（同一窗口读作 735×436），不能与这里的物理像素直接比较；工具统一用扩展边框。

> **追加（2026-11-15 显示身份核查）**：上面 2940×1846 会话的主显示器是 `\\.\DISPLAY16`，适配器 `DeviceString=GameViewer Virtual Display Adapter`、适配器路径 `\\?\ROOT#DISPLAY#0001...`（IDD 虚拟显示），当时 AMD Radeon 780M 的 `\\.\DISPLAY28` 为 `attached=False`——即 2940 的数据来自虚拟显示器，刷新率 144Hz 也不是面板的 60Hz。物理面板接回后（`DISPLAY28`，AMD Radeon 780M，`outputTechnology=INTERNAL`，`MONITOR\LEN9123`，2880×1800@60、200%、工作区 2880×1704），用 1.1.3 构建实测窗口 `EXT=(720,426)-(2160,1298) 1440×872`、`GetDpiForWindow=192`，与本表 200% 档逐项一致，说明本表数字在物理面板上可复现。物理面板即用户实际使用环境（虚拟屏为当时远程会话产生，仅作对照，无需恢复），故本表 200% 档与 QS 栏间隙/跟手的 `panel60` 数据均为官方基线。QS 栏间隙与跟手另见 [quick-switch-attach.md](quick-switch-attach.md) 的 `panel60` 复测。

### 1.3 加宽后的行布局复查

- 行结构为「30 DIP 图标 + 星号内容列 + 右侧自动列」，加宽只让内容列变宽，不改变行高与间距；
- 名称走 `LpHighlightText`，长名按字符省略；路径 `TextTrimming=CharacterEllipsis` 保留；
- 时间与类型标签贴右（资源管理器惯例），行中部留空属预期；两档实拍均无溢出、无文字贴边；
- 空态文案与底栏提示仍居中/贴边距排列，无拉伸变形；
- 失焦即隐藏、`Esc` 清空并隐藏、`Enter` 打开选中项等既有行为未改动。

## 2. 已知限制

- 混合 DPI 多屏（两屏缩放不同）下主窗几何只有探针数值，未做真机实拍；
- 125% / 150% 本版未实拍，结论以探针数值留档为准；
- 窄屏下限 560 DIP 只在探针的 1024×768 合成工作区上验证，未使用真实小屏。
