# 验证缺口：代理指标（2026-11-15）

> 用途：记录历史上「代理指标通过就当成目标通过」的结论，标明哪些需要按真实目标重验。
> 状态口径以 [功能状态清单](功能状态清单.md) §0.1 为准；本文件只登记缺口，不改功能代码。
> 触发这次核查的是提权开关：只用「计划任务注册 / `RunLevel` / 命令行」证明「以管理员身份运行」，
> 而用户目标是「双击后进程真的在高完整性级别」。

## 1 判定标准

代理指标 = 能自动测、可复现，但不是用户目标本身的量。三问里第 3 问为否，即判为缺口：

1. 这个量通过时，用户目标是否**一定**达成？
2. 若不一定，差在哪一环？
3. 差的那一环有没有**独立**证据？

典型形态：

| 形态 | 代理 | 目标 |
| --- | --- | --- |
| 配置即行为 | 计划任务已注册、`RunLevel=HighestAvailable` | 进程令牌真的是 High |
| 元素即交互 | 界面有数字徽标/键帽、UIA 能读到 | 真实按键真的选中/跳转 |
| 几何即观感 | 矩形间距 = 8 DIP、`between=0` | 看着贴边、不重叠、不闪 |
| 采样即跟手 | 位置延迟 12–18 ms、`settled=True` | 人拖动时觉得跟着走 |
| 接口即结果 | `Shell_NotifyIconW` 返回 `ok=True` | 用户看见气泡 |
| 截图即现状 | 有图 | 图里的版本/文案与当前构建一致 |

## 4 判为不属于此类（避免误伤）

| 结论 | 指标 | 为什么指标即目标 |
| --- | --- | --- |
| 8 DIP 圆角 + 单层 DWM 描边 | 栏右边缘逐像素 RGB | 目标就是像素：第 0/1 像素同色、第 2 像素进底色 |
| 窗口几何（半屏宽 / 顶边 1/4 / 高 436 DIP） | 窗口矩形 | 目标就是矩形本身 |
| 主题 / 配色 / 密度 / 不透明度 | 截图 | 目标是画面，截图就是画面 |
| 拖放 5/5 | 真实资源管理器拖拽 + 日志 + 目标目录打开 | 链路即目标 |
| 加速镜像 6/6 | 真实下载 + SHA256 与清单一一致 | 目标就是拿到正确字节 |
| `Tab` 范围切换 | 真实三次 `Tab` + 提示与行标签同步变化 | 真实按键，不是等价入口 |

## 5 处置顺序

| 优先级 | 项 | 理由 |
| --- | --- | --- |
| P0 | #1、#2 | 数字键是唯一被降级的行；真实按键链完全没测 |
| P0 | #12 | 过期截图会继续被当证据引用 |
| P1 | #3、#4、#5、#6 | 影响「界面/跟手」这类只能靠看的结论 |
| P2 | #7、#8、#9、#10、#11、#13 | 低风险或已有部分证据，随下轮功能回归一起补 |

## 6 结论

- 已按真实目标重验 2 项（提权、截图版本，见 §2）；§3 共 13 项：1 项已降级待重验（#1 数字键 1–6），其余 12 项仍按原结论登记、需重验。
- 共性根因：把「能自动测的量」当成验收目标，且没有在结论里写清「这个量不能证明什么」。
- 后续规则：任何记为「已验证」的结论，必须写明测的是哪一环；如果测的不是用户目标，结论里要显式标注「代理指标，目标未验证」。
