# Pathleap 1.1.3 发布说明

发布日期：2026-11-15
版本：`1.1.3`（上一正式版 `1.1.2`）
tag：`v1.1.3`

版本号按 [版本号规则](版本号规则.md) 进位：`1.1.2` 升一个 patch 即 `1.1.3`（`patch` 上限为 10，未越界）。
本版只修一个会影响使用的崩溃缺陷，其余行为与 1.1.2 相同。

## 1. 修复：提权开关点一下即崩溃

设置 → 更新页的「始终以管理员身份运行」开关，点击后会调用 `ShellExecuteExW` 以管理员身份
注册/删除计划任务。该 API 声明在 `user32.dll`，但实际导出在 `shell32.dll`，调用必然失败；
异常从 `async void` 事件里逃逸，触发 `APPCRASH combase.dll`（异常码 `0x80131523`），
窗口直接消失，计划任务也不会创建。

修复：`Platform/ElevationService.cs` 的 `DllImport` 改为 `shell32.dll`。

## 2. 验证

按用户确认的界面点击链路实测（设置 → 更新页，UIA `Toggle`，同一进程内取日志与任务状态）：

- **开启 9/9**：开关 Off→On；`schtasks /Query` 找到任务；`AlwaysRunAsAdmin=True`；
  状态行「当前进程：标准权限 · 计划任务：已注册」；日志「计划任务已注册」+「始终以管理员身份运行: 已开启」；
  任务 `RunLevel=HighestAvailable`、`Triggers` 为空、命令指向当前 exe 且带 `--elevated-launch`；
  截图 [81-settings-elevation-on.png](shots/81-settings-elevation-on.png)。
- **关闭 7/7**：任务删除；`AlwaysRunAsAdmin=False`；状态行「计划任务：未注册」；
  日志「计划任务已删除」+「始终以管理员身份运行: 已关闭」；
  截图 [82-settings-elevation-off.png](shots/82-settings-elevation-off.png)。

环境说明：本机 UAC 策略 `ConsentPromptBehaviorAdmin=0`，提权请求**静默通过、没有弹出确认框**；
因此「用户手动点 UAC 确认」这一分支没有被走到，其余链路均为真机真操作。

## 3. 未验证项（如实列出）

1. **UAC 弹框的人工确认分支**：本机策略不弹框；换到默认策略的机器上，首次点击会出现一次 UAC，
   该交互未实拍。
2. 提权后的开机自启链路仍沿用 1.1.2 的实现，本版未改动、未重复验证。
3. 其余未验证项（真实 SMB、Firefox、鼠标注入、UIPI 拖放等）与 1.1.2 相同，见
   [1.1.2-发布说明](1.1.2-发布说明.md) §5。

## 4. 已知限制

- 计划的提权任务没有触发器，只在登录时由应用通过 `schtasks /Run` 显式调用；
- 计划任务名固定为 `Pathleap-Elevated-<当前用户 SID>`，多用户共用同一台机器时各用户各一份；
- 其余与 1.1.2 相同。

## 5. 影响范围与升级

- 配置无变化；已注册的计划任务不需要迁移；
- 升级后第一次点击提权开关即可正常注册任务；
- 其余功能与 1.1.2 相同。
