# 界面观感诊断（2026-11-15）

> 起因：用户反馈「不难看，但很普通，没有高级感，具体哪里不好看说不上来」。
> 本文件只做诊断与方向，不改主线代码；方向截图来自真实构建（200% 真机），改动均为临时资源，拍完已还原。

## 1 七项逐条诊断

### 1.1 层次

| 项 | 当前实际值 | 判断 |
| --- | --- | --- |
| 窗口与背景 | 窗口底色 `#171A21`，以 92% 不透明度叠在系统磨砂上；根节点没有渐变、没有阴影 | 与桌面靠磨砂区分，但窗口自身是一块平色 |
| 面板之间 | 搜索区/列表/底栏三层：列表 `#171A21`、底栏 `#1B1F27`，对比度 **1.05:1**；分隔只靠 1 DIP 发丝线（`Border1` = 7% 白） | 面板之间几乎无色差，分离基本由一根 1px 线承担 |
| 选中行 | 强调色按 87%→80% 混入底色的横向渐变 + 20% 强调色描边；实测 `#1B233B` 对页面 **1.12:1** | 选中能看见，但强弱只由「很淡的色块 + 细描边」表达 |
| 阴影 | **全仓 0 处** `ThemeShadow` / `DropShadow`；只有 DWM 的 1px 外框和 8 DIP 圆角裁剪 | 没有「浮起」层级，所有面板都在同一平面上 |

结论：层次靠「1px 线 + 5% 色差」两招，没有第三个信号（阴影、内高光、材质、模糊），这是读起来「平」的第一来源。

### 1.2 字排

| 项 | 当前实际值 | 判断 |
| --- | --- | --- |
| 字族 | 正文全部默认 UI 字族（Windows 上即 Segoe UI Variable）；另有 Consolas（键帽）、Segoe Fluent Icons（图标）、Segoe UI Symbol（`↵`） | 正文只有一个字族，没有为标题/元信息做字族区分 |
| 字重 | 只有 Normal 与 SemiBold 两档（`UpdateWindow` 另有 1 处 Medium） | 两档够用，但选中行名称会从 Normal 变 SemiBold，**选中时字宽变化会引起轻微重排/闪动** |
| 字号阶梯 | 令牌 11 档：9.5 / 10 / 10.5 / 11 / 11.5 / 12 / 12.5 / 13 / 14 / 16 / 20；密度切换再产生 12.5 / 13.5 / 14.5 | 13 档里有 6 档只差 0.5，训练不出「这是标题、那是正文、那是脚注」的直觉 |
| 三级信息 | 名称 13.5 SemiBold（选中）/ Normal `Text1` 14.84:1；路径 11 `Text3` 5.4:1；时间 10 `Text4` **3.71:1**；标签 9.5 `Text3`；分组标题 10.5 SemiBold + 字距 130 | 三级存在，但最小的两级（10 / 9.5）落在 3.7:1，低于小字 4.5:1 的常用下限 |
| 数字 | 时间列用默认比例数字，**没有等宽数字**（`TextBlock` 未设 `FontFeature`，也没用等宽字体）；列宽 `MinWidth=46` | 时间右对齐但字宽不等，逐行读数会轻微跳动；46 DIP 只够 `12:34`，到「昨天 23:59」会挤 |

结论：字号「多而密」、行内层级靠 1~2px 字号差，缺少真正拉开的对比；最小元信息对比度不足。

### 1.3 密度

| 项 | 当前实际值 | 判断 |
| --- | --- | --- |
| 行高 | 紧凑 34 / 标准 46 / 宽松 56 DIP，行间距固定 1 DIP | 三档可用，但同一档内所有行等距 |
| 行内 | 图标 30、名称与路径 `Spacing=2`、左侧行内边距 10 | 名称与路径贴得够紧 |
| 页面 | 搜索区 18/18/18/16，分组头 20/13/20/5，列表滚动区 2/4/2/0，底栏 42 | 上下左右留白几乎处处 18~20，组与组之间没有更大的呼吸 |
| 组间对比 | 最近访问只有一个组，组头到首行 5 DIP、行到行 1 DIP | 「组内更紧、组间更松」不成立：组间反而比行间还紧 |

结论：间距是「均匀铺开」而不是「有节奏」；视觉上像把内容平均分配，缺少留白做主语。

### 1.4 圆角与描边

| 项 | 当前实际值 | 判断 |
| --- | --- | --- |
| 半径档位 | 4（键帽）/ 5（`↵` 徽标）/ 6（控件）/ 7（按钮、品牌点、图标块）/ 8（卡片、窗口）/ 10（大圆角）/ 12（空态图标块）/ 999（胶囊） | 8 档，且 6/7/8 只差 1 DIP，肉眼分不出层级，反而增加不一致感 |
| 描边 | 1 DIP 发丝线；白 7%（Border1）/ 14%（Border2）/ 20%（Border3）；200% 下实际渲染 2 物理 px | 线本身不重，但 14% 的 Border2 被用于行、标签、键帽、窗口外框，出现频次高，整体偏「框感」 |
| 分隔线 | 搜索区下 1 条、底栏上 1 条，均为 Border1 | 两条线的位置说明清楚，问题是它们和行描边同色，争夺注意力 |

结论：圆角不是「少而稳」，而是「多而近」；描边不是重，而是到处都是，导致界面读起来像表格。

### 1.5 色彩

| 项 | 当前实际值 | 判断 |
| --- | --- | --- |
| 强调色 | `#3563E6`（HSL 约 224°/76%/55%）；悬停 `#3F6BE8`、按下 `#294FBD` | 饱和度高，且和中性灰的蓝偏同向，整体偏「科技蓝」的默认感 |
| 使用面积 | 品牌点 22×22、`↵` 徽标 22×20、命中字标记背景、选中行渐变、选中行描边、`知道了` 按钮 | 面积不算大，但同时出现在 5 类位置，强调色不「单点」 |
| 中性灰 | 窗口 `#171A21`、`#1B1F27`、`#232833`：蓝通道始终最高（冷偏约 5~10） | 冷灰本身没问题，问题是没有冷暖对比，五档灰在明度上只差 3~5% |
| 选中态 | 渐变填充 + 细描边（不是纯色整块填充） | 这一条比常见实现好；弱点在色块太淡（1.12:1），离开屏幕稍远就看不出来 |
| 语义色 | Ok `#3FBF8C`、Warn `#E0A14A`、Danger `#F0705E`，与强调色同亮度 | 状态色饱和度也偏高，底栏状态点因此和强调色抢视线 |

结论：不是「颜色太多」，而是「一套冷灰 + 一个高饱和蓝」没有形成主次；强调色铺得散，反而不显得克制。

### 1.6 动效与反馈

| 项 | 当前实际值 | 判断 |
| --- | --- | --- |
| 出现/隐藏 | 窗口显示、隐藏无自定义过渡（依赖系统） | 不拖沓，但也没有「从哪来」的空间感 |
| 结果刷新 | 直接替换列表，无淡入、无错落 | 输入时列表瞬变，长列表会有跳变感 |
| 悬停 | 行背景瞬时切换（10% 白），无过渡 | 反馈存在但硬切 |
| 键盘选中 | 选中态瞬时切换，方向键滚动用 `ChangeView(..., disableAnimation: true)` | 跟手优先，但代价是零缓动，观感偏「工具」 |
| 全局 | 全仓无 `Storyboard` / `DoubleAnimation` / `CompositionAnimation` | 这是「普通感」最直接的一条：没有任何一处有节奏 |

结论：动效不是「太少装饰」，而是「完全没有时间维度」；所有状态都是 0ms 切换。

### 1.7 图标

| 项 | 当前实际值 | 判断 |
| --- | --- | --- |
| 体系 | 全部为 `Segoe Fluent Icons` 字形（非矢量线性图标）；另有 1 处 `Segoe UI Symbol` 的 `↵` | 字形体系统一，但无法控制线宽 |
| 字号 | 11（清除历史）、13（分组图标）、15（工具按钮）、16（行图标）、19（空态） | 五档；同屏里 13/15/16 混用，视觉重量不一致 |
| 笔画 | 200% 实拍：行图标、标题栏最小化横线均为 **2 物理 px**（=1 DIP）；100% 下即 1 px | 1px 在 100% 会有抗锯齿发虚，200% 才实 |
| 光学对齐 | 图标块 30×30 + 16 字形居中；字形自身留白不同（文件夹/网页/程序视觉重量不同），未做逐字形偏移补偿 | 同一列图标看起来会一大一小 |
| 键帽 | Consolas 9.5，键帽 17 DIP 高、4 DIP 圆角、下边 2px 边 | 键帽是全身最「有质感」的部件，反衬出其余部分的平 |

## 2 成因归纳

把七项合起来，「普通」不是某一个参数错，而是四个结构性原因：

1. **只有两个分离手段**：5% 色差 + 1px 线。没有阴影、没有材质、没有内高光，所以所有面板都像贴在同一张纸上。
2. **字号阶梯过密、字重只有两档**：13 档字号里一半只差 0.5，读者无法从字号判断层级；同时最小元信息 3.71:1，弱到「看不清」而不是「安静」。
3. **间距均匀、缺少节奏**：18~20 的留白处处相同，组间不比组内松，视觉上没有主语。
4. **没有时间维度**：所有状态 0ms 切换，界面像静态截图；键盘优先的产品反而最缺「跟手之外」的反馈。

## 3 三个方向

三个方向都是「气质取向」，不是三套随机配色；A/B 只动配色令牌（`ColorThemes.json` 的 indigo 暗色一套），C 另外把密度切到「宽松」（真实配置项）。拍完均已 `git checkout` 还原，主线代码零改动。

### 方向 A：静默中性（更克制的灰 + 单一低饱和强调色）

- 取值：窗口 `#15171A`、底栏 `#181B1F`、强调 `#4F63C8`、描边降到 6%/11%/17%、悬停提到 7% 白。
- 意图：去掉「科技蓝」的默认感，让灰更像灰；强调色只负责「当前行」和「回车」，不参与装饰。
- 截图：`93-dirA-neutral-empty.png`、`94-dirA-neutral-results.png`。
- 代价：更安静，也更接近「没有设计」；需要靠排版和间距补回辨识度，否则会从「普通」滑向「寡淡」。

### 方向 B：层次与材质（更强的表面阶梯）

- 取值：底色压到 `#0E1014`，抬起面 `#1C2129`、`#232A34`、`#2D3542`；描边 8%/16%/24%；强调 `#4D7CFF`；标题栏渐变加深。
- 意图：用更深的底 + 更亮的抬起面拉开「底/面/浮层」三级，让搜索区、列表、底栏不再同一平面。
- 截图：`95-dirB-layered-empty.png`、`96-dirB-layered-results.png`。
- 说明：这次只演示了配色阶梯。真正要「材质」还需要结构改动——行内顶部 1px 内高光、列表与底栏之间的柔和投影、结果行改为卡片。这些都要动 `MainWindow.xaml` 和代码，本阶段按约定不改主线。
- 代价：深底 + 高对比描边在 100% 下容易显脏；投影在磨砂窗口上需要和 DWM 圆角一起调，成本最高。

### 方向 C：清晰编辑感（暖中性 + 琥珀强调 + 宽松密度）

- 取值：窗口 `#1A1917`、抬起面 `#232120`、文本 `#F0EDE8`/`#B5AFA6`、强调 `#C98A3E`（墨字 `#201203`）；密度切「宽松」：行高 56 DIP、名称 14.5。
- 意图：把「工具感」换成「阅读感」；暖灰降低冷蓝的默认感，琥珀只出现在选中与回车；更松的行让长路径更好读。
- 截图：`97-dirC-editorial-empty.png`、`98-dirC-editorial-results.png`。
- 代价：暖色 + 高行高会减少一屏可见结果数（436 DIP 高下从约 7 行降到约 5 行）；琥珀与 Warn 色相近，状态点需要另配冷色。

## 4 选型后的最小改动清单（供落主线时参考）

| 方向 | 必改 | 可延后 |
| --- | --- | --- |
| A | `ColorThemes.json` 的 indigo 暗色一套；`Text4` 提到 ≥4.5:1；字号阶梯压到 5 档（10 / 11 / 13 / 16 / 20） | 数字等宽、图标字号统一到 16/13 两档 |
| B | A 的配色基础 + `MainWindow.xaml` 行内高光、底栏投影、结果行卡片化；`ThemeService` 增加 elevation 令牌 | 动效（120~160ms 淡入） |
| C | 暖色配色一套 + 默认密度改「宽松」；`Text4` 提亮；时间列改等宽数字 | 键帽与行图标的光学对齐 |

三个方向都不包含「展开详情」——如果用户要的是可展开的行内详情，那是功能改动，不在观感范围内，需要单独立项。

## 5 本轮没做的事

- 没有改任何主线资源或代码；临时配色与密度均已还原并重建 Release。
- 没有拍悬停态（原因见 §0），也没有伪造第三张截图。
- 没有做动效原型：动效需要真实交互录制，静态截图无法证明缓动曲线。
